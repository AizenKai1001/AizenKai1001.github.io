Pico Audio Lab

How much useful music and signal experimentation can I extract from a tiny microcontroller speaker when the software is designed around its electrical and acoustic limits?

THE PROJECT

A MicroPython audio lab for a Raspberry Pi Pico microcontroller: dual-pin differential PWM drives a tiny speaker, while companion tools generate public-domain melodies, reduce MIDI to a monophonic top voice, and optionally transcribe audio into a note sequence shaped for the speaker’s limits.

The speaker driver owns the low-level behavior

The MicroPython driver creates an inverted two-channel PWM pair for differential drive, exposes note-to-frequency conversion, melody playback, sweeps, beeps, coarse volume control, and startup/audio LED diagnostics, and explicitly releases the outputs when playback ends.

The music tools reduce richer sources honestly

One path writes a public-domain Beethoven theme directly as notes; another parses MIDI and keeps the highest active voice while preserving the file’s tempo map. Playback adds short articulation gaps so repeated notes remain distinct on the single-tone speaker.

Audio transcription is an experiment, not a recorder

The optional desktop transcription tool band-limits a source, proposes spectral pitch candidates, uses a Viterbi-style path to suppress octave flicker, folds obvious register errors, and emits a monophonic melody. Its own comments describe the output as a chiptune approximation rather than faithful mixed-audio reproduction.

RECORD & SCOPE

Source review covered speaker.py, demo.py, beethoven.py, midi2song.py, playsong.py, and transcribe.py. “Raspberry Pi Pico W — Capability Map + Project Ideas” was used only to confirm Pico-versus-Pi scope; its proposed project ideas are not claimed as built.
