Media Library Automation

How can a long-running browser and media job finish cleanly, keep partial files out of the library, and release its resources?

  • n8n
  • Playwright
  • FFmpeg
  • Jellyfin
  • Shell scripting
ORIGINAL CATEGORY STUDY · tools
THE PROJECT

A personal n8n workflow connecting a supplied media link, browser-based source discovery, FFmpeg processing, and a Jellyfin library. It stages unfinished files separately, hands off completed downloads, closes the browser after success, and selects available storage so routine transfers do not need manual supervision.

From an input to a completed file

The recorded workflow accepts a URL at runtime, reads metadata, follows the configured provider chain, and hands a resolved stream to a background FFmpeg helper. It builds on the custom n8n Browser service, while the existing library workflow handles completed-file organization.

Completion is a distinct event

Incomplete media is kept outside the watched import area. A successful final move triggers the browser-close callback and library refresh behavior. The recorded implementation also prefers a second media disk and retains a fallback when that storage is unavailable.

Recorded verification and scope

The September 15 build note records an end-to-end download/import, a successful browser cleanup callback, and the resulting library database entry. This is a specific personal workflow, not a universal media downloader; source websites and their integrations can change.

RECORD & SCOPE

“n8n Browser Movie Extract Verification Fix”, September 15 additions: dynamic input, server fallback, completed-file handoff, end-to-end verification, browser cleanup, and second-disk layout. Operational URLs and credentials are excluded.
